## 专用服务器启动

依次运行两版原生开发服务器，不安装 FTB 和带 `-PftbIntegration` 各一次。测试世界仅绑定回环地址，使用离线模式；`http.enabled=false`，网络桥启用。开发集成依赖不打包进发布 jar。

| 加载器 | FTB 组合 | 启动与诊断 | 结束 |
| --- | --- | --- | --- |
| Forge | 无 Chunks | 选择无领地全员可授权策略 | `stop` 保存完成，退出 0 |
| NeoForge | 无 Chunks | 选择无领地全员可授权策略 | `stop` 保存完成，退出 0 |
| Forge | Chunks 2001.3.8 / Library 2001.2.9 / Teams 2001.3.1 / Architectury 9.1.12 | `/cctlive network policy` 返回 FTB 管理器 ready | `stop` 保存完成，退出 0 |

四组 CC:T terminal/wired_query 能力均可用，未创建服务端 HTTP endpoint，没有专用服务器误加载客户端类的问题。通过测试用本机 RCON 执行诊断与 `stop`；RCON 只是测试启动配置，不是 mod 的网络桥要求，不应为使用 mod 开启公网 RCON。

Forge 首次集成启动发现 LegacyForge 的 modRuntimeOnly 没有自动带入 FTB 的必需 mod，已显式补充 Library、Teams、Architectury 后重验成功。启动器进程退出 0 本身不足以证明游戏启动，以上同时检查 `Done`、实际策略输出和保存记录。初次信号终止记录不作为最终干净退出证据。

## 审查后修复（2026-10-21，第二轮）

对 `41b1a89` 的源码审查确认三个问题并已修复，均未经实机验证：

| 问题 | 来源 | 修复 |
| --- | --- | --- |
| P1：`source` 读取直接连接的显示器只检查电脑位置；显示器伸入他人领地时可读取其终端 | 第三方审查，源码核对属实 | 读取前按显示器多方块结构覆盖的每个区块执行 FTB 双许可检查（`Terminals.monitorBlocks`、`NetworkAuthorization.checkBlocks`）；`status.monitors` 过滤无权显示器；显示器被拒不撤销电脑授权 |
| P2：hello 只发一次，首次握手超时后整个连接持续 503 | 第三方审查，源码核对属实 | `NetworkClient` 按 1～30 秒退避重试，调用时也触发；仅 426 协议不兼容停止重试；握手完成前不显示授权按钮 |
| 单人游戏回归：客户端桥在集成服务器上同样启动，且 CLI 只要存在 `client/` 目录就永久改用网络桥，导致单人世界的 attach/输入/文件/Lua 等管理员本机工具全部不可用 | 本轮审查 | 自己的集成服务器不启动客户端桥；CLI 仅在 `client/endpoint.json` 存在时使用客户端桥，同一 MCP 连接用过网络桥后仍不回退 |

## 授权图标与三项小修（2026-10-21，第三轮）

- 授权入口改为单个 16×16 “AI” 图标：位于整个电脑/海龟界面左侧外（CC 电源/终止侧栏是界面最左一列），顶端与 `TerminalWidget` 的上缘齐平；左侧放不下时放入侧栏列、CC 两个按钮下方（`NetworkButtonLayout`）。图标状态通过新增 RPC `menu_grant` 向服务端查询本人当前界面的授权，点击后经原授权数据包切换；本机 HTTP 桥不能路由该操作。应用协议升到 3。
- 限流：每连接每秒第一次超限回复 429，其余丢弃（`NetworkRateLimit`）。
- 撤销：界面撤销不再要求电脑可用/已加载，只校验界面归属；无法识别电脑时提示使用命令。平板电脑授权请求回复“暂不支持”，不再静默。

自动化：`:mod-forge:test`、`:mod-neoforge:test` 各 53 项通过（新增限流与图标位置测试）；`:cli:test` 45 项 0 失败 2 跳过；`:engine:test`、`assembleMods` 成功。图标的实际渲染、悬停提示和点击往返需图形客户端验收。
