## 2026-10-21 已确定规则与讨论边界

本节依据用户最新规则更新，取代初版清单中关于按查看、编辑、执行等能力细分玩家权限的建议。规则确定不代表运行时代码已完成修改；NET 项继续按实现及验证情况保持 `open`。

| 事项 | 当前结论 | 确定程度 |
| --- | --- | --- |
| 权限类别 | 对一名玩家和一台目标电脑，只区分“有权限”和“无权限” | 已确定 |
| 授权来源 | 已认领区同时满足 FTB 方块交互与编辑有效许可；未安装 FTB 领地组件或未认领时所有玩家可发起授权 | 已确定，适配待实现 |
| 荒野例外 | 未认领区即使启用 FTB `no_wilderness`，仍允许所有玩家发起授权 | 已确定 |
| FTB 兼容 | 已核对两种版本的公开接口及保护实现；不能只判断是否同队 | 源码静态核对完成，依赖编译和联调未完成 |
| 多人协作 | 只防止多个 MCP 会话同时操作；不拦截原生 CC:T 界面，不因打开界面自动撤销 MCP 控制 | 已确定，锁细节待设计 |

权限、功能可用性和操作占用分别判断：有权限不表示尚未实现的功能已经可用；被其他会话占用不等于变为无权限。路径校验、只读 ROM、配额和服务器统一功能开关仍然有效，但不据此新增玩家权限等级。

FTB 接入应由服务端查询目标电脑所在维度、位置的实际保护规则，并结合团队权限返回最终允许/拒绝结果。已认领区要求交互许可与编辑许可同时有效，不仅比较是否同队。未认领区的全员可授权明确优先于 FTB `no_wilderness`，这是本 mod 授权策略的例外。

操作互斥的推荐方案是服务端维护以电脑为目标的独占 MCP 控制租约：绑定玩家、连接和独立 MCP 会话，原子获取，其他会话收到占用结果，同一持锁会话的副作用操作也要串行执行。释放、断线、到期、权限失效或电脑卸载时停止接受旧请求，收束在途提交后才可交接；旧锁令牌不能继续提交任务。该方案尚未实现，不拦截玩家手动操作及电脑程序自身活动，因此文件版本和可靠提交保护仍然必要。

仍需讨论的边界：

- FTB 组件已安装但 API 未就绪或查询失败时，推荐返回服务不可用而非当作未安装放行；具体依赖及故障处理待实施验证。
- FTB 公开通用保护接口使用玩家所在维度；已认领电脑跨维度操作如何适配，是否先限同维度；移动目标如何定位和重新判断。
- 其他 MCP 会话的旁观读取是否可与持锁控制并存；原生界面不受 MCP 锁拦截已经确定，不再作为待定选项。
- 锁的期限、续期、等待或拒绝策略、主动交接和管理员强制收回规则；相同电脑 ID 共享磁盘或共享外设时的互斥范围。

最新判定流程、上游源码依据和锁状态草案见 [FTB 授权与 MCP 会话互斥方案](network-authorization-lock-design.md)。该方案将已确定规则与建议参数分开；FTB 依赖编译和实际兼容行为仍需在 Forge 1.20.1 与 NeoForge 1.21.1 分别验证。NET 项继续保持 `open`。

## 已有基础与当前限制

当前已实现两种加载器的客户端入口、游戏网络通道、版本及能力握手、本机 HTTP 桥、电脑界面查看授权、撤销，以及授权列表、状态和当前屏幕读取。

现有保护包括本机回环监听、Bearer 令牌与 Host 校验；玩家身份来自游戏数据包上下文；授权绑定实际连接和电脑实例，固定 30 分钟、读取不续期，断线与实例失效后不可继续读取；RPC 有请求编号、连接 epoch、响应分块、体积和并发限制。

当前原型返回 `observe` 标记，网络入口只实现查看，拒绝文件、Lua、输入、开关机、快照、trace、HTTP body 和外设查询；这是当前实现范围，不再作为未来权限等级划分的依据。原有管理员本机 HTTP 功能仍保留，但不能直接作为多人网络权限实现复用。

已验证两版构建、各 33 项 mod 测试、CLI 40 项通过及 1 项 Java 8 检查跳过；两个专用开发服务器在关闭 HTTP 时启动成功。真实客户端授权按钮、玩家连接的数据包往返及多玩家隔离尚未完成实机验收。使用说明和原验证边界见 [网络桥第一版](../docs/development/network-preview.md)。

## 权限与执行规则

### NET-01 — 授权来源、FTB 权限与失效规则

- 当前依据：`NetworkServer.authorize` 验证当前菜单、菜单编号、`stillValid`、CC:T `checkUsable`，默认仅 OP 可授权；普通玩家授权由服务器配置开启。尚无独立的电脑所有权、成员名单或领地策略。
- 最新决定：已认领区以 FTB Chunks/Teams 的方块交互与编辑有效许可同时允许为条件；未安装领地组件或未认领时所有玩家可发起授权，未认领区不因 `no_wilderness` 拒绝。最终只返回“有权限”或“无权限”，不要求自建 CC:T 所有者体系。
- 已核对：两个上游分支都有公开管理器、交互/编辑保护类型及团队隐私处理；通用保护入口使用玩家所在维度。具体提交和事实见 [方案文档](network-authorization-lock-design.md#二上游源码静态核对)。这是静态核对，未完成依赖编译或实际兼容验证。
- 待完成：实现两版可选适配、有效双许可判定、无领地分支和故障处理；解决跨维度目标查询。单纯读取团队属性不能冒充通用保护入口的完整语义。
- 待确定：离开距离、跨维度、移动目标、退出团队、领地规则变化和管理员身份变化的处理；明确哪些条件需持续验证，以及权限失效后的锁释放和任务终止规则。
- 验收：交互允许但编辑拒绝、编辑允许但交互拒绝均不可授权；两项允许才通过。验证无 FTB、未认领含 `no_wilderness` 全员可授权，以及团队/领地设置、非 OP、伪造菜单、移动目标、跨维度和权限来源故障。

### NET-02 — 二元权限与功能可用性

- 当前依据：`NetworkGrants` 没有 scope 字段，网络原型只开放查看并返回 `observe` 标记；这尚不是完整操作的统一权限实现。
- 已确定：只使用“有权限”和“无权限”，撤回初版的查看/读取/编辑/执行等多级 scope 建议。判定针对玩家与目标电脑，不按工具追加玩家权限等级。
- 待完成：统一权限检查入口；有权限者可在服务器已实现、已启用的功能及操作锁规则内使用目标电脑，无权限者不能借其他工具访问。协议能力、服务器统一功能开关及路径/大小限制分别处理。
- 规则要求：说明完整授权包含运行 Lua、输入、文件编辑和外设控制等已开放功能的实际影响；同一权限结论不能被不同入口绕过。
- 验收：所有工具分别覆盖有权限和无权限；另测试功能未开放、目标被占用和路径越界，错误结果不能被误报为新的权限等级。

### NET-03 — 控制会话互斥、租约与撤销

- 当前依据：网络授权是按玩家连接隔离的固定期限查看授权；原 `LiveSession` attachment 尚无完整的玩家及授权归属模型。
- 已确定：只防止多个 MCP 会话同时操作；原生 CC:T 界面不被锁拦截，打开界面不自动撤销 MCP 控制。MCP 互斥由服务端保证，不以客户端按钮禁用或“都是队友”为保证。
- 推荐实现：以电脑为目标原子获取独占控制租约，持有人绑定玩家、连接及控制会话；其他会话收到占用结果，同一持锁会话内也串行提交副作用操作。多个本机 MCP 会话不能因共享玩家身份而绕过互斥。
- 规则要求：权限检查与锁检查相互独立；玩家只能正常续期/释放自己的租约。释放、断线、到期、失权或卸载后拒绝旧请求，收束在途提交再交接，迟到任务提交前复查锁令牌及版本；管理员强制收回策略继续讨论。
- 待确定：是否允许其他 MCP 会话旁观读取、共享磁盘/外设的锁范围，以及锁期限、续期和等待策略；60 秒租约、15 秒 MCP 心跳等仅为 [参数建议](network-authorization-lock-design.md#六释放断线与旧任务)，未定案。
- 验收：两名有权限玩家同时申请仅一个控制会话成功；第三方不能续期或释放。覆盖同玩家多 MCP 会话、同会话并发、旧锁/交接竞态；原生界面手动操作应继续可用且不自动撤锁。

### NET-04 — 目标绑定与授权版本

- 当前依据：RPC 带请求 UUID 和客户端连接 epoch；服务端授权检查实际连接及电脑实例，数字 ID 重复时拒绝读取。尚无写操作使用的服务器/世界目标绑定、授权编号及授权版本。
- 待完成：操作至少绑定服务器/世界会话、玩家连接、电脑实例、授权编号及版本、请求编号；MCP 任务需要校验预期目标，不能切服后自动对新目标继续写入。
- 规则要求：从有权限变为无权限后，已有授权和锁失效；再次获得权限产生新授权版本，旧排队任务不得使用新授权继续执行。旧版本协议或任务字段不得绕过二元权限及控制锁检查。
- 验收：覆盖切服、切世界、重连、电脑替换、重复 ID，以及撤销后重新授权时迟到的旧任务。

### NET-05 — 请求去重、结果查询、超时与取消

- 当前依据：请求 UUID 用于关联返回，没有执行结果缓存或副作用去重；`NetworkClient` 超时后移除待处理请求。请求编号本身不等于防重放。
- 待完成：对有副作用操作保存有界的执行状态和结果；相同请求返回同一任务结果，同编号不同内容必须拒绝。明确缓存期限和过期后的查询行为。
- 规则要求：区分已接受、执行中、已提交、已取消、失败及结果未知。超时仅说明客户端未收到结果；不得直接宣称未执行，也不得盲目重试。
- 验收：重复、并发重复、同编号不同内容、提交后响应丢失、取消与提交竞态；已提交操作不能报告成未执行的取消。
- 历史关联：[MOD-14](mod.md#mod-14--onserver-超时后已开始任务仍执行) 记录旧 HTTP 超时后任务继续执行的问题；网络任务协议需要独立落实，不能直接宣称原问题已修复。

### NET-06 — 统一业务服务及执行时权限检查

- 当前依据：旧 `LiveHttp` 与新 `NetworkServer` 各自处理业务；旧接口主要依据本机管理员令牌和全局 attachment，缺少多人操作上下文。
- 待完成：抽取统一服务层，显式接收可信的操作者、目标、二元权限判断、授权版本、控制锁和请求上下文；游戏网络入口不允许通过内部 HTTP 转发取得管理员权限。
- 规则要求：在真正执行前重新校验权限与目标实例；长任务在关键提交点检查是否仍允许提交。已经提交的副作用不能仅靠撤销授权自动回滚。
- 验收：任务排队期间撤销或换实例；两个入口复用服务时，网络入口不能调用管理员专有能力。

## 文件编辑、传输与恢复

### NET-07 — 网络文件 API 与版本

- 当前依据：网络入口拒绝文件操作；原 `ComputerFiles` 已有路径检查、只读 ROM、读取长度限制和磁盘配额，可作为实现基础。
- 待完成：开放受权限控制的 list/stat/read/write；删除、移动等操作分别定义，不默认开放。约束编码、偏移、大小、路径范围和错误返回。
- 规则要求：读取返回 hash 或版本；修改携带 `expected_hash` 或等价前置条件。不得返回服务端磁盘路径，也不能把服务端目录当作玩家本机路径使用。
- 验收：越界路径、ROM 写入、编码边界、空文件、大文件和旧版本写入；数据只来自当前授权的电脑及路径。

### NET-08 — 可靠提交、冲突与运行中编辑

- 当前依据：原 `ComputerFiles.write` 的覆盖模式使用 `TRUNCATE_EXISTING` 直接写目标文件；尚无网络编辑的条件提交协议。
- 待完成：在权限及文件版本匹配时完整提交；采用与 CC:T mount 和配额兼容的暂存、替换或恢复方案，并明确实际原子性边界。
- 规则要求：上传未完成、磁盘满或提交失败时保护旧文件；并发修改返回冲突。多文件提交须提供事务式一致性，或明确限制并通过停机/版本目录等方案避免读到半更新状态。
- 待确定：与 CC 程序自身写文件的竞争如何协调、修改何时生效、哪些操作需要暂停或重启电脑。
- 验收：中途失败、空间不足、程序并发写、两名编辑者、部分提交与进程中断；验证旧文件和恢复结果，不能仅检查返回码。

### NET-09 — 上传分块、完整性与背压

- 当前依据：请求上限 4096 字符；已有响应 16 KiB 分块及 256 KiB 总量限制，没有文件上传协议。
- 待完成：上传标识、分块序号、预期总长度、完整性校验、提交和取消；限制单次上传、单连接、全服暂存空间及生命周期。
- 规则要求：不完整内容不能成为正式文件；撤销、断线、超时后清理暂存数据。发送需要背压和带宽预算，不能仅把大数据拆成大量游戏包。
- 验收：超限声明、缺块、重复块、错误长度/hash、断线和慢速传输；验证资源释放和正常游戏延迟。

### NET-10 — 快照归属与恢复冲突

- 当前依据：原本机接口已有快照能力，网络入口未开放；历史上已登记重复电脑 ID 的 trace/快照归属问题。
- 待完成：为快照定义服务器/世界、电脑存储身份、操作者或共享范围、创建版本及保留期限；恢复沿用目标电脑的二元权限并检查控制锁，不新增恢复专用玩家权限。
- 规则要求：恢复前返回覆盖及删除范围；检测创建快照后的并发修改，防止静默抹除他人的新内容。明确恢复失败和部分恢复的处理方式。
- 验收：跨玩家、跨世界、重复 ID、恢复期间撤销、冲突及失败恢复。实例身份与 CC:T 实际共享磁盘语义须一并确认。
- 历史关联：[MOD-20](mod.md#mod-20--重复电脑-id-时-trace快照目录冲突)，不重复登记为新漏洞。

### NET-11 — 诊断数据及外设的受控开放

- 当前依据：网络只返回当前状态/屏幕，不提供历史 trace、HTTP body 或外设调用；原 `PeripheralQuery.READ_ONLY` 根据方法名称判断读取类方法。
- 待完成：trace、HTTP 正文和外设接口沿用目标电脑的二元权限，另限制数据范围、分页和查询成本；服务器统一的外设安全策略不作为额外的玩家权限等级。
- 规则要求：不能只按电脑数字 ID 读取历史；不能用 `get`、`is` 等名称前缀严格证明第三方外设方法无副作用。
- 验收：未授权历史数据、跨玩家正文引用、查询超限及带副作用的第三方方法；没有可信策略时拒绝执行。
- 历史关联：[MOD-13](mod.md#mod-13--read_only-白名单是名称启发式)、[MOD-20](mod.md#mod-20--重复电脑-id-时-trace快照目录冲突)。保留 MOD-13 原有无法仅靠静态确认第三方行为的边界。

## 当前边界加固与数据治理

### NET-12 — 入队前限流及全服资源预算

- 当前依据：Forge 使用 `consumerMainThread`，NeoForge 默认主线程处理；`NetworkServer.handle/authorize` 执行时才进行每连接计数限制。已有请求/响应大小及客户端待处理数量限制，但不能因此断言主线程排队已受保护。
- 待完成：在安全的网络接收阶段限制入队量，加入有界队列、全服并发/字节/耗时预算、响应发送预算及公平调度；不能在网络线程访问世界对象。
- 规则要求：在生成和序列化大结果前控制工作量；限流错误与丢弃策略需兼顾可诊断性和响应放大风险。
- 验收：单连接及多连接压力、队列耗尽、大屏幕/诊断结果、慢客户端；记录 tick 延迟、内存、排队和恢复情况。当前未登记已复现的攻击结果。

### NET-13 — 本机发现地址与令牌边界

- 当前依据：`LiveTools.endpoint` 从发现文件直接读取 URL，`send` 向该地址携带 Bearer 令牌；客户端桥自身的回环监听和 Host 校验并不替代 MCP 发出请求前的目标验证。
- 待完成：明确并实现合法 scheme、回环地址、端口、userinfo 和重定向策略；禁止因发现文件中的外部 URL 向其他目标发送令牌。保留断线后不回退旧管理员接口的行为。
- 规则要求：客户端和服务端管理员令牌继续隔离，令牌不进入游戏数据包或日志；明确 Windows 等平台的访问权限及令牌更换/失效策略。
- 验收：外部地址、混淆地址、非回环解析、非法 scheme、userinfo 和重定向均不能获得令牌；正常动态回环端口继续可用。不要把能修改本机文件等同于远程服务器已能修改发现文件。
- 历史关联：[CLI-01](cli.md#cli-01--endpointjson-的-url-未校验即发送-bearer-令牌)，作为同一问题的网络桥应用场景引用。

### NET-14 — 状态、通知、错误与能力展示

- 当前依据：授权结果主要通过聊天提示，界面没有完整授权状态同步；握手失败没有完整恢复流程；部分异常或限流直接丢弃请求。MCP 工具目录仍包含网络入口未开放的工具。
- 待完成：显示连接、握手、可用、失败和断开状态；结构化通知授权成功、拒绝、过期与撤销。提供受控重试，重连不得自动恢复已失效授权。
- 规则要求：统一错误码、可重试性及任务状态；按协商能力展示或明确拒绝不可用工具。扩展写入时需调整当前 `negotiate` 要求 `read_only=true` 的原型策略，不能继续硬编码只读能力组合。
- 验收：没有服务端 mod、版本不兼容、握手超时、拒绝授权、过期、切服和能力变化；用户与 MCP 均能判断实际可用范围。

### NET-15 — 数据隔离、脱敏、审计与清理

- 当前依据：网络授权按连接隔离且不开放历史数据；未来文件、trace、HTTP 正文和快照会扩大数据范围。尚无完整的网络操作审计及数据生命周期策略。
- 待完成：按服务器/世界、电脑及授权范围隔离数据；配置敏感字段隐藏/脱敏、存储配额、保留期限、清理和导出规则。
- 规则要求：记录授权者、操作者、目标、操作、时间、结果及必要 hash，默认避免复制令牌、完整源码或敏感正文。URL 参数、请求头、文件和响应正文都可能含凭据。
- 数据边界：授权返回给客户端的内容可能继续进入本机 MCP 和模型上下文；撤销只能阻止后续访问，不能收回已返回的数据。需在授权说明中明确这一点。
- 验收：跨玩家数据引用、脱敏、审计关联、保留清理和配额耗尽；记录清理失败的恢复行为。
- 历史关联：[MOD-18](mod.md#mod-18--body-文件与-sessions-目录从不清理)、[MOD-20](mod.md#mod-20--重复电脑-id-时-trace快照目录冲突)。

### NET-16 — 身份、代理与传输信任

- 当前依据：操作者取自游戏连接上下文，可靠性依赖服务器的玩家认证和代理转发设置。复用游戏连接本身不能证明任意部署都具有可信身份或加密传输。
- 待完成：明确支持的 `online-mode`、代理转发与信任配置；对离线或不可信身份环境，规定禁用、受限运行或额外身份绑定策略。
- 规则要求：不接受数据包自报 UUID 作为认证；区分客户端本机接口保护、玩家身份认证和游戏链路加密。信任边界包括运行 mod 的服务端及被信任代理。
- 验收：在计划支持的部署模式中验证身份绑定；拒绝不可信的转发身份，文档不得承诺配置本身不提供的身份/加密保证。

## 控制扩展与验收

### NET-17 — 网络控制工具及生命周期

- 当前依据：网络入口仅接受列表、状态、屏幕及能力查询；attach/detach、输入、点击、任意事件、Lua、开关机等尚未接入。当前状态显式标记无 trace，基于 trace 事件的等待不可用。
- 待完成：在 NET-01～NET-06 规则落实后，逐项接入工具并统一执行二元权限与控制锁检查；Lua 的临时文件、超时后结果领取、清理与取消必须归属于对应任务和授权。
- 规则要求：不能直接转发任意 HTTP 请求或服务器文件路径。控制电脑与控制其外设、红石及世界效果的权限含义应在授权时说明；等待和订阅不得阻塞游戏主线程。
- 验收：分别验证每个工具的拒绝、成功、超时、断线、撤销及清理路径；不能因多个工具组合而取得未授予的能力。

### NET-18 — 双版本真实端到端验收

- 当前依据：既有自动测试覆盖纯 Java 授权容器、协议、本机 HTTP 和内存游戏传输替身；专用服务器启动仅证明初始化及客户端类隔离，不能代替真实玩家交互。
- 待完成：在 Forge 1.20.1 与 NeoForge 1.21.1 分别运行真实客户端和专用服务器，以两个玩家执行授权、读取、撤销及隔离测试；服务端 HTTP 关闭时仍应工作。
- 现阶段验收：有效/失效菜单、非 OP 策略、屏幕及显示器、断线重连、切服、卸载、重复 ID、版本不兼容，以及对未安装 mod 的对端的兼容行为。
- 写入开放前验收：验证 FTB 双许可、未安装或未认领（含 `no_wilderness`）全员可授权；验证两名有权限玩家和同玩家多会话互斥、原生手动操作不受 MCP 锁拦截、旧授权/锁版本、重复请求、取消、撤销竞态、并发修改、上传中断、磁盘满和压力测试。需覆盖真实 `ServerPlayer`、菜单及加载器数据包，而不只是测试替身。
- 证据要求：记录版本、提交、配置、实际参与角色、步骤、预期/实际结果和清理结果；没有执行的项目保留待验证，不用通过的单测数量替代。
