# 联合测试 3：Mod 更新检查看板（网络 + 显示器 + 持久化）

这一项用来测试 AI 能否写出一个**比较复杂、需要联网**的 CC: Tweaked 程序，同时检查 Skill 的测试引导：
- 能用模拟器测的部分（解析、比较、界面、触摸、缓存）先在模拟器里测；
- 模拟器测不到的部分（HTTP）到实机上验证。

提示词里**故意不写怎么用测试工具**。

## 准备

| 项目 | 要求 |
|---|---|
| 工具 | 最新的 cct-run（19 个工具）、cct-live mod、Skill；`files.allow_write = true` |
| 游戏 | 一台新的**高级电脑**：顶部接一块高级显示器（至少 4×3 格），左侧接一个扬声器。可选：背面接一个无线调制解调器，再准备一台手持高级电脑 |
| 网络 | 游戏所在的电脑要能访问 `https://api.modrinth.com`。可以先在 CC 电脑里运行 `wget https://api.modrinth.com/v2/project/create` 试一下 |
| 对话 | 新开一个对话 |

【要做什么】
1. 程序从电脑上的一个文本文件读取这份列表（每行一个文件名，文件由你创建）。
   以 .disabled 结尾的是已停用的 mod，单独列出来，不检查更新。
2. 从文件名里识别出 mod 的名字和已安装的版本。文件名格式各不相同；识别不出来的，要如实标成“无法识别”，不要猜。
3. 通过 Modrinth 的公开 API 查询每个 mod 有没有适用于 1.20.1 + Forge 的更新版本，判断结果分为：
   已是最新 / 有更新（显示新版本号）/ Modrinth 上找不到 / 无法判断 / 查询失败。

4. 显示器上显示看板：
   - 顶部是汇总（各种结果各有几个、上次检查的时间）；
   - 下面是列表，不同结果用不同颜色；
   - 列表放不下时可以触摸翻页，触摸某一行显示这个 mod 的详细信息（已装版本、最新版本、发布日期），再触摸一次返回。
5. 每 30 分钟自动重新检查一次；触摸看板上的“立即检查”按钮也能手动检查。检查过程中看板上要显示进度。
6. 查询结果保存到电脑上。重启后先显示上次的结果，再在后台重新检查。网络不通时，继续显示上次的结果，并标明“离线，数据来自 xx 时间”。
7. 发现新的更新时，扬声器提示一次（同一个更新不要重复提示）。
8. （可选）如果背面有无线调制解调器，就用 rednet 广播一条简短的汇总，并写一个手持电脑上用的小程序来接收和显示。

- 要礼貌地使用 Modrinth API：请求带上能说明来源的 User-Agent，同时进行的请求不超过 3 个，遇到限流或网络错误要等待后重试，不能无限重试。
- 检查的过程中，看板要能正常响应触摸，不能卡住。
- 程序开机自动运行，但不要覆盖我现有的 startup.lua（用别的方式接入）。

【交付与测试】
写好之后先测试，再部署到我游戏里的 <ID> 号电脑上运行，确认看板显示正确、触摸翻页和详情可用、联网查询的结果合理。
<ID> 号电脑可以接管，可以在上面创建和修改文件（不要覆盖 startup.lua）。测完请把电脑上与本程序无关的改动恢复原样，然后释放。
最后告诉我：哪些在模拟器里测过、哪些在游戏里测过、哪些没测到，以及你对查询结果的抽查（至少挑 3 个 mod，说明你是怎么确认结果正确的）。

## 需要观察

**需求和设计**
- 是否先拆解需求、确认布局（显示器大小、扬声器在哪一面），并给出默认假设；
- 有没有指出难点：文件名格式不统一；有的 mod 不在 Modrinth 上；版本号格式不同、很难比较（例如 `0.7.48r`、`6.0.8`、带 `+1.20.1` 的）；
- 联网和界面是否放在**并行**的结构里（`parallel` 或用事件驱动的 `http.request`），而不是在界面循环里同步调用 `http.get`；
- 有没有限制并发数，重试有没有次数上限和等待时间。

**测试**
- 是否用模拟器测了：文件名解析（尤其是格式特殊的几个）、版本比较、显示器排版、触摸翻页和详情（fixture 里注入 `monitor_touch`）、缓存的读取和“离线”显示；
- 是否明确说明模拟器测不了 HTTP，并在实机上测；
- 实机上：
  - 有没有先用 `cct_live_lua` 确认外设所在的面，以及 Modrinth 能不能访问；
  - 是否用 `cct_live_trace`（`kind: api/handle`，或用 `contains` 过滤）检查实际发出了哪些请求、收到了什么响应；有没有用 `cct_live_body` 看响应内容；
  - 有没有核对并发数和 User-Agent；
  - 有没有用 `cct_live_snapshot` 在改动前保存、结束时恢复（只保留本程序的文件）；
  - 有没有断网或限流的测试（例如临时改错 API 地址），并在测完后改回来；
- 抽查结果时，是否说明了确认的依据（比如把 Modrinth 网页上的版本列表和程序的判断对照），而不是只说“看起来正确”。

**结果**
- 看板在实机上能不能正常显示和翻页；
- 有多少个 mod 判断为“无法判断”或“找不到”，理由是否合理；
- 测完后电脑上除了程序本身的文件，有没有残留其他改动（`/.cctlive` 是否为空）。
