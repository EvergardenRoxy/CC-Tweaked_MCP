# 联合测试 5：高级电脑自动制作 Create 精密构件

状态：**实验设计，尚未执行**。本轮按用户要求，从双产线订单改为精密构件（Precision Mechanism）自动装配；环境保持 Minecraft 1.21.1 / NeoForge。参考[联合测试 3](../reports/03-factory.md)、[联合测试 4](../reports/04-orders.md)的事件、外设、中文与恢复经验。

核心目标：高级电脑控制真实加工，完成**同一工件的五轮装配**，识别最终成功或失败，按实际成品自动补产，并能解释暂停/重启后的物料状态。本文件及[独立提示词](../prompts/05-precision-mechanism.md)均为设计，不是已完成的游戏实测。

后续实际测试改用了**单置物台＋单机械手**，并明确要求中文翻牌库存显示；条件变化、上传会话核验与代码复跑见[测试报告](../reports/05-precision-mechanism.md)。本设计保留为原始方案，不用它替代实际执行条件。

## 先分清两个计数

按题设，完整加工一件工件后的成功概率为 **80%**；五次循环是工艺步骤，不能理解成五次独立的 80% 判定，不能用 `0.8^5` 计算成品率。

常见配方如下，**先以本整合包 JEI、实际加工及可读取的配方数据核实**，不把原版经验当作已确认事实：

| 部分 | 常见配方 / 本轮预期 |
|---|---|
| 初始底材 | 金板 `create:golden_sheet`，每次尝试 1 张 |
| 每轮装配 | 小齿轮 `create:cogwheel` → 大齿轮 `create:large_cogwheel` → 铁粒 `minecraft:iron_nugget`，由三台机械手按序加工 |
| 循环 | 上述三步重复 **5 轮**，合计 **15 次装配操作** |
| 中间件 | `create:incomplete_precision_mechanism`，携带 Create 保存的加工进度 |
| 最终成功 | 精密构件 `create:precision_mechanism`；按题设概率 80%，须核实整合包配方 |
| 最终失败 | 配方定义的其他结果；可能返回金板或齿轮等，具体种类/数量现场确认并单独分流 |

如果整合包修改了输入、步骤、循环数或概率，先记录差异并调整实验参数。程序可以支持配置，但验收时的实际配方必须与声明一致。

**每次尝试**指一张新金板开始加工，最终得到一次成功/失败结果；中间件回流不算新尝试。失败返回几件副产物，也只算一次失败结果，不能按副产物件数累加失败次数。

## 采用单件在途的检查箱回路

首轮使用三台机械手，**整条回路最多一件工件在途**。每完成一轮三步加工，工件先进入电脑可读写的检查箱；电脑分类后才决定下一步。这使五轮、失败分流与故障恢复都能被观察和验收。

```text
金板原料箱 ──电脑定量投入 1 张──→ 进料缓存箱 ─→ 受控上料 ─→ 传送带
                                         ↑                  │
                                         │            机械手 1：小齿轮
                                         │            机械手 2：大齿轮
                                         │            机械手 3：铁粒
                                         │                  │
                                         └──未完成件回送── 检查箱
                                                            ├─精密构件→成品箱
                                                            ├─失败结果→副产物箱
                                                            └─未知/混料→暂停核对

三个独立辅料箱 ─→ 补料通道 ─→ 对应机械手
高级电脑 ─有线网络→ 原料/辅料/缓存/检查/成品/副产物箱、高级显示器
         └红石或已实测的控制外设→ 上料闸门、加工段离合器
```

关键约束：

- 检查箱没有无人控制的出口；中间件必须经电脑决定才回送。终态分类优先于循环计数，成功品和失败结果都不能再进装配带。
- 优先用普通箱子的通用 inventory 能力定量转运；机械手靠实际供料通道补料。不能假设传送带、机械手或漏斗自带 CC 专用 API。直接控制设备的能力必须先探测。
- 各箱连接方向、上料闸门的“断电”状态和离合器电平先手动验证。尽量设计成电脑无控制信号时禁止新增投料；已在途工件允许进入检查箱等待。
- 机械手依靠真实 Create 配方完成加工；不能用电脑把原料直接替换成成品、用命令生成结果，或只等待固定秒数就宣布完成。
- 三个辅料通道各自固定材料，防止错误补料；传送带速度以机械手能完成对应步骤为准。
- 回路只服务本轮工件，不与其他产线混料；成品和副产物箱不被玩家或其他物流取放。单件在途是首轮验收前提，批量并行留到扩展轮。

第一件由操作者手动验证三步顺序、五轮、最终结果、检查箱回流和补料。探测中间件能读到的详情：通用 inventory 的 `nbt` 可能仅是指纹，**不能假设可读取 Create 的具体轮次字段**。没有进度字段时，用受控回箱检查点记录正常轮次；重启后不确定的轮次显示“待核对”，真实是否完工以 Create 物品状态与最终结果为准。

建议目标单：**收齐 8 个精密构件，最多尝试 20 次**。若配方符合上表且所有暂存处初始为空，物料上限为：

| 原料 | 对应 20 次完整尝试的预算 |
|---|---|
| 金板 | 20 张 |
| 小齿轮 | 100 个 |
| 大齿轮 | 100 个 |
| 铁粒 | 100 个 |

按 80% 估计，8 个成品平均需要 10 次尝试，即约 10 张金板和三种辅料各 50 个；**平均值不是保证**。达到 20 次仍不足 8 件时报告实际缺口并停下，不能无限补料或伪报完成。失败返回物先隔离，不自动当新金板/辅料回收；需要回收时另立明确的物料账。

## 控制逻辑与恢复要求

程序至少区分以下状态，具体代码结构由被测 AI 设计：

```text
空闲 → 核对库存/输出空间 → 预留新尝试 → 定量投料 → 加工中
                                                  ↓
                                             检查箱收料
                            ┌─────────────────────┼─────────────────────┐
                         未完成件               精密构件              失败结果
                            ↓                      ↓                     ↓
                     记录检查点并回送       记成功、送成品箱       记失败、送副产物箱
                            └────继续当前尝试      └────核对账目后决定是否新投一张────┘

任意状态 → 缺料 / 堵料 / 外设离线 / 状态不确定 → 保留现场、暂停并提示
```

- 显示 `order_id`、目标与已收成品、已投尝试、成功/失败、当前工件、已确认轮次/步骤、三种辅料、暂停原因和更新时间。没有步骤传感/数据时，不把估计步骤显示成已确认事实。
- 五轮由 Create 工件进度实际约束；电脑的计数服务于调度和核对，不能覆盖或重造工件数据。正常无中断实验应观察到五轮、每种辅料各消耗五份；没有足够证据时不得声称精确读到了内部进度。
- 尤其检查第五轮结束：看到未完成件不判成功；看到精密构件才计实际成品；看到已确认的失败结果计失败，不再作为“第六轮”加工。遇到跳站、超过预期回流或未知物品先诊断暂停，不盲目投入新底材。
- 每次转运看实际返回数量和源/目标库存，不能将一次调用成功等同于转移成功。缺辅料、检查箱/输出堵塞、设备离线都要保留当前工件，禁止另投金板。
- 暂停采用“停止新增投料，当前件停在可解释位置”；急停可立即停动力，但恢复时必须盘点。取消订单同样先处理当前在途件，并把其结果单列为取消后收尾。
- 订单、请求去重、尝试预留、转运意图、检查点和终态记账持久化。电脑文件与 Minecraft 库存**没有跨系统原子事务**：重启必须联合检查持久状态、各缓存和成品数量，防止“转移后未记账”造成重复投料/计数。不能只把内存轮次清零后重做。
- 任意时刻重启可能无法恢复准确轮次。允许继续加工已明确识别的同一未完成件并等待真实终态，界面注明轮次未知；无法确认物品归属或账目时暂停核对。不得声称单凭轮次数实现任意崩溃下的 exactly-once。

## 统计口径与账目

采用两个模式，均只有一个活动任务：

| 模式 | 用途与停止条件 |
|---|---|
| 定次试产 | 例如加工 10 张金板；完成 10 次终态判定后停止，报告实际成品率。不能要求恰好 8 个成功 |
| 定量订单 | 例如目标 8 个成品、最多 20 次尝试；失败后自动补投，实际收齐即停止；到上限则报告不足并停止 |

相同请求 ID 重试不重复开单；同 ID 内容变化拒绝。本轮不再要求双产线调度或五单排队，重点放在加工闭环。

在没有取消/丢失工件、单件在途的受控条件下，账目应满足：

- 已实际投入的金板尝试数 = 成功次数 + 失败次数 + 当前未终结的尝试数（0 或 1）。仅预留而尚未转入的尝试另列，不冒充已投。
- 实际成品新增量对应成功输出；默认每次成功 1 件，若配方改过输出数量则据实配置。副产物按种类/数量另账，不作为订单完成量。
- 标准配方完整结束一次，三种辅料各实际消耗 5 份；对账包括补料箱、料斗和机械手里的余料，不只看供料箱减少量。读不到的库存由玩家停机清空回收后核对。
- 取消后收尾、隔离件、未知/遗失件单列，不能为了让公式平衡把未知损失填成随机失败。

短样本比例不是 80% 配方的证明。概率以实际配方核对为基础，实机记录实际波动；若另做大样本统计，独立报告样本量与不确定性，不用“恰好 80%”判程序对错。

## 实施顺序与模拟用例

1. 备份与校准：记录 startup.lua hash、库存、动力/红石初态，跑通一件真实五轮加工。
2. 被测 AI 探测真实外设、库存详情、控制方式；保存电脑文件快照和第一版代码。传感器/配方未知项明确列出。
3. 在模拟器中验证状态机与账目，再部署到 `/nf-precision-test/` 及批准的新自启入口，不覆盖 startup.lua。
4. 首次交付后冻结程序，维护者独立验收；失败、修复和复测分别留档。
5. 导出证据，停投料并处理当前件，恢复无关文件及设备设置、释放控制。电脑快照不能恢复方块/物料/世界配置，完整复位使用世界副本。

模拟器不自带 Create 装配物理和随机配方。使用实机采样的 `scripted` 返回值、库存和时间线构造**确定性测试**，其结果不冒充真实成品率。至少覆盖：

- 一次完整五轮，前四轮始终是未完成件，第五轮才成功；重复事件不多执行一轮或多投一张。
- 终态序列固定为“失败、成功、失败、失败、成功”：目标 2 件应恰好结束 5 次尝试，成功 2、失败 3；标准配方合计 25 轮、75 次装配操作。返回金板的失败也必须分流。
- 连续失败直至尝试上限，任务明确未完成且停止新投料；不能用 80% 期望值虚增成功数。
- 第三轮缺铁粒后恢复、检查箱满/转移返回 0、成品箱堵塞、副产物箱堵塞、外设报错、状态损坏。
- 在投料前后、回送前后、终态记账/转运前后恢复，检查实际库存与日志，无法确定时暂停；普通状态查询与暂停在阻塞外设轮询期间仍可处理。

## 维护者独立验收

每项独立准备初始库存与订单。未触发的情况记 **未测**；模拟故障通过与真实故障通过分开记录。

| ID | 操作 | 通过标准 |
|---|---|---|
| A1 配方与回路 | 核对 JEI、实际方法/箱名/电平，手动跑一件 | 确认真实三步顺序、五轮、进度物品和终态；检查箱能截留，无额外底材混入 |
| A2 单件五轮 | 空回路投入 1 张，观察检查点与三种辅料前后存量 | 同一工件五轮三步共 15 次装配；最终不论成功/失败都收料停止。只有一张底材投入，终态不回送，无“第六轮” |
| A3 真实随机失败 | 做固定 10 次尝试的试产，记录每次终态 | 实际投入 10 张且终结 10 次，账目吻合；成品率据实显示，不强求 8/10。若未遇到某种副产物，其分流实测记未测；另由确定性用例验证失败分支 |
| A4 自动补产 | 下目标 8 件、最多 20 次的任务 | 每次失败后补投新金板，实际成品收齐才完成；到上限不足则明确报告不足并停止。不能把随机未达目标单独判为控制程序失败 |
| A5 中途缺料 | 第三轮前在停机可操作位置取走铁粒供给并清空该通道余料，再补回 | 保留同一未完成件，不另投金板，不伪增轮次；补料后继续真实剩余加工，不从新底材重做 |
| A6 假转移与堵料 | 先在模拟器令转移返回 0；实机独立用例中分别令成品箱和副产物箱无可用容量，记录人为填箱的基线 | 不按“调用过”计收料成功；在检查箱保留终态，停新投料并说明阻塞；清障后只计一次，不将终态回送，人为填入量不算生产结果 |
| A7 在途重启 | 第三轮检查箱稳定停留时重启；另在第五轮加工/终态转运附近做一次重启 | 同一未完成件保留，订单和已成功量不归零、不重复投料/计数；不确定的轮次如实显示或暂停，不能跳步伪造完成。两个重启位置分别留证 |
| A8 重进世界 | 工件在回路中时退出世界再进入，不动各箱 | Create 物品实际进度延续；程序自启并盘点恢复或明确等待核对，startup.lua hash 不变；AI 按既有授权重新发现端点和接管 |
| A9 分类与幂等 | 对确定性用例使用返回金板/齿轮等失败结果；实机重发同一订单 ID，再发送冲突内容 | 副产物永不算成品，也不自动混回原料；一次请求只创建一次任务，冲突拒绝。没有真实出现的副产物不能写成已实测 |
| A10 失联与账目异常 | 中途断开一个关键缓存箱网络；独立副本中损坏状态文件或制造无法解释的库存差异 | 程序不崩、不继续盲投，不把未知工件消失算成 20% 失败；可恢复时盘点，否则明确暂停核对。未在游戏实际做的故障另标模拟覆盖 |
| A11 人机与响应 | 加工中发 10 个不同 ID 的查询，夹入暂停/继续；有聊天框时由玩家真实发中文命令并确认回复 | 所有 ID 可核对，显示持续更新，普通确认目标 2 秒；聊天发送按实测冷却排队不静默丢失。无 AP 则终端/显示器验收，聊天项单列未测 |
| A12 可复现与收尾 | 重跑自动用例、核对物料账与文件 diff | 五轮/失败/上限/恢复用例可重复；新目录及批准自启之外无关文件不变，临时文件清理；先处理在途件再恢复安全设备状态并释放 |

A2 的五轮不能靠代码里的计数或固定延时自证，要用受控检查点、真实工件变化和三种辅料消耗交叉核对。A3 若 10 次均成功也可能发生，不能为获得失败而改配方后声称验证原概率。实机未出现失败时，应在预算允许下另开试产；用例中的固定失败序列始终标为模拟。
