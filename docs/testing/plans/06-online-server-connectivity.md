# 在线服务器连通性测试（网络桥）

目的：证明玩家通过**已有的 Minecraft 连接**加入远程服务器后，本机 `cct-run mcp` 能经 cct-live 网络桥读取自己授权的电脑，且服务器不需要开放任何额外端口。本测试只覆盖 0.3.0 的只读数据通道（列表、状态、屏幕、会话、锁）；文件、Lua、输入、trace 等仍被网络桥拒绝，**拒绝本身就是测试项**。

本地功能测试（模拟器、单人世界的 cct-live）不在范围内，见[测试指南](../guide.md)。

## 被测链路

```text
cct-run mcp / 探测脚本 ──127.0.0.1 HTTP+令牌──▶ 客户端 mod ──Minecraft 连接──▶ 远程服务器 mod ──▶ CC:T
        L1 本机发现与鉴权            L2 握手/协议/延迟            L3 会话  L4 授权与拒绝  L5 锁与读取  L6 长连接
```

每一层失败时，后面的层没有意义；按层定位故障点。

## 准备

| 项目 | 要求 |
| --- | --- |
| 服务器 | 部署 cct-live 服务端 mod（与客户端同一版本、同一加载器与 Minecraft 版本）和 CC:T 1.120.2；`config/cctlive-common.toml` 中 `[network] enabled = true`；服务端 `[http] enabled = false` 也可 |
| 客户端 | 同版本 cct-live 客户端 mod；**不能是单人世界或自己开放的局域网**（那是本机管理员端点，不走网络桥） |
| 本机 | cct-run 同版本（应用协议 3）；Python 3.8+（探测脚本） |
| 测试电脑 | 服务器里至少两台电脑：A 电脑（授权用，开机，屏幕上有可辨认的文字）、B 电脑（**不授权**，用于负向测试）。有 FTB Chunks 时，另备一台在他人领地内的电脑 |
| 账号 | 玩家 P1（非旁观）；做 T7 时再加一名玩家 P2 |
| 记录 | 服务器地址与版本、是否经反向代理/隧道/跨国线路、客户端位置、`/cctlive network policy` 输出 |

## 自动部分：探测脚本

玩家加入服务器后，在**玩家本机**运行：

```sh
# 1) 只查链路（不需要授权）
python3 scripts/online-connectivity-test.py --game-dir <客户端游戏目录> --report link.json

# 2) 游戏里先给 A 电脑授权（界面左侧 AI 图标，或在电脑旁 /cctlive network authorize <ID>），再查锁和读取
python3 scripts/online-connectivity-test.py --game-dir <客户端游戏目录> --computer <ID> --burst --report full.json

# 3) 长连接：保持会话和租约 10 分钟，每 15 秒心跳 + 读状态
python3 scripts/online-connectivity-test.py --game-dir <客户端游戏目录> --computer <ID> --soak 600 --report soak.json
```

授权 30 分钟到期，第 3 步前可重新点击授权。退出码 0 全部通过，1 有失败，2 未能连上本机桥。

| 编号 | 检查 | 失败时的含义 |
| --- | --- | --- |
| L1.1–1.2 | `client/endpoint.json` 为回环地址的 `minecraft-network`，所属进程存活 | 未加入服务器 / 游戏已退出残留文件 / 在单人世界 |
| L1.3–1.5 | 无令牌、错令牌 401；非本机 Host 403 | 本机桥鉴权被削弱 |
| L2.1 | `GET /network` 经游戏连接返回 200 | 503：握手未完成或服务器没装 mod；426：协议不兼容；403：服务器关闭了 `network.enabled`；504：服务器无响应 |
| L2.2–2.4 | 协议 = 3；10 个操作齐全；`read_only` 与 `exclusive_control` 为真 | 版本不一致、服务端不是 0.3.0 |
| L2.5 | 20 次往返的最小/中位/p95/最大延迟与丢失 | 以 p95 < 2 s、零丢失为通过线；客户端单请求 10 秒超时 |
| L3.1–3.5 | 开会话、同 open key 幂等、心跳、未知会话 403、授权列表 | 会话表满（每连接 8 个）或连接 epoch 变化 |
| L4.1–4.5 | 未授权电脑 acquire/status 被拒；文件/输入/Lua/trace 路由 403；非空请求体 413；未知查询参数 400 | **网络桥暴露了不该有的能力（安全缺陷）** |
| L4.6 `--burst` | 约 60 次/秒请求出现 429 | 服务端限流（每连接 20 次/秒）没有生效 |
| L5.0–5.9 | 授权电脑出现在列表；acquire；status/screen；control 查询；第二会话抢锁 409；冒用租约被拒；release；旧租约 409；释放后可交接 | 锁或授权逻辑错误 |
| L6.1 `--soak` | 长时间心跳 + 读取零失败 | 连接被中间设备掐断、租约过期、服务器卡顿 |
| L7.1 | 关闭会话后心跳 403 | 会话未清理 |

脚本是只读的：只开自己的 MCP 式会话，抢锁后会释放，不向电脑写任何东西。

## 手动部分

下列项脚本无法做到，需要人在游戏里配合。每项记录“预期 / 实测 / 日志”。

| 编号 | 步骤 | 预期 |
| --- | --- | --- |
| T1 授权入口 | 打开 A 电脑界面，点击左侧 AI 图标（白→绿）；再点击（绿→白） | 授权/撤销生效；`cct_live_computers` 随之出现/消失；撤销后已持有的锁立刻失效 |
| T2 命令授权 | 站在电脑 8 格内 `/cctlive network authorize <ID>`；离开 >8 格、换维度、电脑未加载各试一次 | 只有第一种成功，其余明确提示 |
| T3 真实 MCP 客户端 | 配置 `cct-run mcp --live <目录>`，让 AI 依次调用 `cct_live_computers` → `cct_live_control {acquire}` → `cct_live_status` → `cct_live_screen` → `release`；屏幕内容与游戏里一致 | 全链路通过；对写类工具（`cct_live_type` 等）明确返回网络桥不支持，不得改变电脑 |
| T4 授权到期 | 授权后等待 30 分钟，期间只做读取与心跳 | 到期后读取被拒，需要重新授权（读取与心跳不续期） |
| T5 断线重连 | 持锁时：① 退出重进服务器 ② 拔网线 30 秒再恢复 ③ 服务器重启 | 旧锁、旧授权失效；本机 `endpoint.json` 断线删除、重进重建；同一 MCP 进程**不回退**到管理员端点；重新授权、重新 acquire 后恢复；握手按 1/2/4…30 秒退避重试 |
| T6 电脑状态变化 | 被锁电脑关机再开、被破坏、被远离到区块未加载 | 读取返回明确错误，不挂起；恢复后需重新确认授权 |
| T7 多会话/多玩家 | 同一玩家开两个 MCP 连接抢同一台；P1 持锁时 P2 授权并抢同一台 | 都返回占用（409），不抢占；释放后可交接；两名玩家互相看不到对方授权的电脑 |
| T8 FTB 领地（装了 FTB Chunks 时） | 未认领、自己领地、他人领地（交互/编辑四种组合）、`no_wilderness`、跨维度、显示器伸入他人领地 | 与[规则表](../../development/network-preview.md#授权规则)一致；Chunks 未就绪时返回不可用而不是放行；被拒显示器不出现在 `monitors` |
| T9 原生界面并存 | 持锁时在游戏里正常打开并操作该电脑 | 不被拦截、不撤锁、程序不被冻结 |
| T10 网络环境 | 同一套步骤分别在：直连、经反向代理/隧道（如 playit、frp）、VPN 下重复 L2.5 与 `--soak 600` | 记录延迟分布与是否掉线；代理类可能产生更高 p95，不属于缺陷但需记入报告 |
| T11 服务器侧日志 | 全程观察服务端日志 | 无异常堆栈；rate limit、协议不兼容等只出现在预期步骤 |
| T12 版本矩阵 | Forge 1.20.1 服务器 ↔ Forge 客户端；NeoForge 1.21.1 服务器 ↔ NeoForge 客户端；**跨加载器应失败且提示清晰** | 同加载器通过；跨版本 L2.1 失败而不是静默异常 |

## 通过标准

- 探测脚本在 `--computer --burst` 下 **0 FAIL**，且 `--soak 600` 0 失败。
- T1–T7、T11 全部达到预期；T8 在装有 FTB 时全部达到预期，未装 FTB 时记为“不适用”。
- 任何 L4 / T3 里“本不该可用的能力可用”都是阻塞项。
- 延迟（L2.5 p95）和掉线情况只记录，不设硬阈值，除非超过客户端 10 秒超时导致 504。

## 常见故障定位

| 现象 | 可能原因 |
| --- | --- |
| L1.1 失败 | 没进服务器；用了单人/局域网；游戏目录选错（启动器开了版本隔离时是版本文件夹） |
| L2.1 返回 503 | 握手尚未完成（等几秒重试）；服务器没装 mod；掉线 |
| L2.1 返回 426 | 客户端、服务端、cct-run 版本不一致 |
| L2.1 返回 403 | 服务端 `network.enabled = false` |
| L2.1 返回 504 | 服务器或链路卡顿超过 10 秒；代理丢包 |
| 列表里没有电脑 | 未授权、授权过期（30 分钟）、电脑未加载/关机、FTB 判定无权 |
| L5.1 返回 409 | 其他 MCP 会话持锁（或自己上一个会话的锁还没到期，默认 60 秒） |
| 429 | 超过每连接 20 次/秒；降低轮询频率 |
