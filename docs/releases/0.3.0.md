# cct-run 0.3.0

0.3.0 为 cct-live 新增 **Minecraft 网络桥预览**：多人服务器上的玩家可以通过已有的游戏连接，在授权后让自己电脑上的 AI 像本地一样操作自己授权的 CC:T 电脑——读屏幕、读写文件、运行 Lua 和 Lua 文件、输入、开关机、快照、外设查询和 trace。服务器不需要开放额外端口。同时接入 FTB Chunks 领地权限，并让多个 MCP 会话互斥使用同一台电脑。**cct-run、客户端 mod 与服务端 mod 需要一起升级**（网络应用协议 4）。

> **安全提示**：授权等于允许该玩家的 AI 在这台电脑上运行任意 Lua，与玩家坐在电脑前能做的事一致，但 AI 操作更快、范围更大。服务器管理员可用 `network.enabled = false` 整体关闭网络桥，也可保持 `files.allow_write = false`（默认）禁止写入文件。

两个 mod 共享实现，选择与游戏加载器匹配的一个，不要同时安装。使用网络桥时**客户端和服务端都要安装**同一版本；单人游戏和原有管理员本机 HTTP 模式的安装方式不变。CC: Tweaked 仍固定 1.120.2。FTB Chunks 是可选依赖，不随 mod 打包，也不要求客户端安装。

## 网络桥（预览）

- **连接方式**：客户端 mod 在 `127.0.0.1` 随机端口提供带令牌的本机桥，发现文件在 `<游戏目录>/cct-live/client/`；请求经游戏连接转发到服务端。远程服务器不增加 HTTP/MCP 端口。
- **授权后的控制范围**：持有电脑的独占锁后，网络桥提供与原有管理员本机端点相同的功能：状态与屏幕（含显示器和历史屏幕）、文件（list/stat/read/write/delete）、事件与输入（`cct_live_type`/`click`/`event`）、开关机、快照、外设查询、trace 和 HTTP body。`cct_live_lua` 与运行 Lua 文件不需要专门接口，由文件写入加输入事件组成，同样可用。
- **取得锁即开始记录**：`cct_live_attach` 在网络桥上等同 `cct_live_control acquire`，服务端同时开始记录这台电脑（trace、`file_write` 等记录带 `by: ai`，聊天栏按配置提示）；`cct_live_detach` 等同 release。释放、租约过期、撤销授权或断线后，服务端自动结束。玩家用 `/cctlive detach <ID>` 收回后，后续操作返回 409，需要重新获取。
- **写文件需服务端开关**：写文件、`cct_live_lua` 和快照恢复仍受服务端 `files.allow_write` 控制（默认 false），与本机一致；关闭时返回 403。
- **大文件**：游戏请求上限为 10000 字符，更大的写入由客户端桥拆成约 8000 字符的连续追加，每段由服务端校验租约，单次上限仍为 1 MiB。中途失败时响应带 `partial` 和 `written_so_far`，文件可能已写入一部分。
- **授权**：打开电脑或海龟界面，点击界面左侧外、与终端屏幕上缘齐平的 **AI** 图标（白色=未授权，绿色=已授权，点击切换）；或在电脑旁使用 `/cctlive network authorize <ID>`。另有 `revoke`、`list`、`policy` 子命令。授权固定 30 分钟，可随时撤销。手持平板电脑暂不支持。
- **FTB Chunks**：已认领区需要有效的方块交互**且**编辑许可；未认领区（包括启用 `no_wilderness` 时）和未安装 FTB 时，所有非旁观玩家都可授权。FTB 未就绪或查询失败时拒绝访问，不会放行。显示器按其所在区块单独检查，向显示器发送 `monitor_touch` 事件同样检查。每次请求前都会重新检查电脑的 FTB 许可。已认领电脑暂要求玩家与其处于同一维度。
- **MCP 独占会话**：每个 MCP 连接都有独立会话，同一玩家的不同连接也互斥。先用新工具 `cct_live_control {computer, op:"acquire"}`（或 `cct_live_attach`）获取租约，再使用各项工具，用完 `op:"release"`（或 `cct_live_detach`）。心跳自动进行；默认租约 60 秒、空闲 300 秒释放（`network.lease_seconds`、`network.idle_seconds`）。不拦截原生 CC:T 界面。
- **单人世界**：玩家自己的集成服务器（单人或局域网主机）不启动客户端桥，继续使用原有全功能的管理员本机端点。一个 MCP 连接用过网络桥后，断线不会自动切换到管理员端点。

详细说明见 [网络桥使用说明](https://github.com/EvergardenRoxy/CC-Tweaked_MCP/blob/v0.3.0/docs/development/network-preview.md)。

## 配置

服务端 `config/cctlive-common.toml` 新增 `[network]`：`enabled`（默认 true）、`lease_seconds`（30～300，默认 60）、`idle_seconds`（300～86400，默认 300）。网络桥与 `[http]` 互相独立，关闭服务端 HTTP 不影响网络桥。要让 AI 编辑文件，还需在服务端设置 `[files] allow_write = true`。

## 升级时需要注意

- 网络桥的客户端、服务端与 cct-run 必须同为 0.3.0；协议不匹配时握手失败并提示，不会降级。
- 网络桥现在开放控制功能，不再是只读：升级服务器前请确认你接受玩家授权后其 AI 可在被授权电脑上运行 Lua（见上方安全提示）。
- 原有管理员本机 HTTP 模式、模拟器和其他 MCP 工具的用法不变。

升级步骤：替换 cct-run 解压目录，把游戏 `mods/` 中旧 cct-live 替换为对应的 0.3.0 jar（多人服务器的服务端与每个使用网络桥的客户端都要替换），然后重启游戏与 MCP 客户端。
